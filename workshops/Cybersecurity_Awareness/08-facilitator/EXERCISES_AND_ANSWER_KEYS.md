# Exercises and answer keys

## Public profile and cloning (M1)
Show invented job title, project post and colleague names. Ask what a stranger can learn and which facts prove identity. Answer: those details create context but can be copied. Independent established contact is stronger than another message in the same profile.

## Authority roleplay (M2)
Pairs receive an urgent manager request for a normal process exception. Learner states a polite pause, names the established verification contact and explains next step. Swap roles. Good response: “I can help once I verify through the normal approval process.” Credit a specific route and respectful explanation. Do not reward refusing everything without escalation.

## Four-request activity (SL30)
| Card | Hidden truth | Preferred next action | Reason |
|---|---|---|---|
| E9-HR | Genuine HR requester | Verify authorised task and approved sharing route | Authentic identity does not replace data permission |
| Vendor | Genuine change, still unapproved | Use established contact and complete change/approval process | Legitimate sensitive changes need controls |
| Colleague | Genuine account, unauthorised request | Independently verify purpose and report concerning account activity | Known account can carry attacker content |
| Manager | Impersonated urgent exception | Hold, verify through directory, notify owner/security | Deadline and display name do not authorise action |

At first reveal only the visible request, not the hidden truth. Groups choose proceed/verify/report and explain facts required to proceed. 'Verify' is often appropriate before classification. Do not report a verified legitimate HR request as malicious merely because it concerns sensitive data.

## Identity approvals (M4)
| Prompt | What it could grant | Safer action |
|---|---|---|
| Unexpected MFA | Access for a sign-in attempt | Deny and report |
| Supplied device code | Access to the initiating device/session | Do not enter unsolicited code; check purpose |
| App permissions | Access to specified data/functions | Use approved app process |
| Linking QR | Access by a linked device | Link only recognised self-initiated devices |

## Support verification (M5)
Unsolicited support request: contact established helpdesk/ticket independently before remote access. Confirmed ticket: follow normal authorised support procedure and data rules. Do not teach blanket rejection of support.

All exercise cards are fictional and inert. Keep answers in hidden reveal panels and facilitator notes; do not disclose them through initial colours, titles or aria-label text read to the audience.
