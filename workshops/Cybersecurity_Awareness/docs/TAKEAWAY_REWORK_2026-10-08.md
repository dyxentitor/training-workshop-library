# Takeaway presentation rework, 8 October 2026

Scope: `dist/workshop.html` and its sources on branch `clarity-rework`, starting from commit `17c0334` (the 87-slide readability build). The brief: stop presenting every teaching point as a full-width green **Key point** banner pinned above the source line, and present each point where it belongs, without losing any instruction or qualification. Photographs, backdrops, the type scale and the readability splits are unchanged. Design record: `docs/superpowers/specs/2026-10-08-takeaway-presentation-design.md`.

**Slide count: 87 → 88.** One connected takeaway slide, SL23B, follows SL23 (6 min → 4 + 2). Programme 420 minutes, module totals and the 16 pause points unchanged.

## What was wrong, and why (inspected)

The banner was not a template or an absolutely positioned element. `build/build.py` appended a `.keypoint` box to every non-exempt slide's `.foot`, and `.foot{margin-top:auto}` pushed it to the bottom of the flex column, between the content and the source line. Generated layouts (agenda, openers, glossary, recap) rendered the same box and `checks.split_keypoint` moved it into the footer. On vote and reveal slides CSS hid it until `.chosen` / `.revealed`. So every slide reserved the same strip, the point sat far from its evidence, and on the densest slides flex shrink silently squashed the feedback box to make room (the fit check tolerated 24 px past the padding line, which hid this).

## The treatment

- One reusable block, `.takeaway` (`src/css/base.css`): a 2 px teal top rule, an optional small teal label, one bold statement (`--t-h3`), supporting lines at `--t-copy` with a short teal dash, an optional note. Typography and spacing only; no fill, no full-width box. It participates in the slide's grid or stack and is never pinned.
- `.takeaway.row`: statement left, support right, for full-width content (tables, card rows, wide diagrams, decision slides). `.takeaway.row.brief` is a narrower statement column; none needed it in the end.
- `.lesson`: the dedicated takeaway slide (SL23B): one 48 px statement with a teal phrase, three action lines, one note, generous space.
- Labels are used only when they say something: "What Aina should do", "A strong response", "Preferred response", "Answer", "The safer route", "After the exercise", "One habit for today", "One habit". The generic "Remember" label is used only on SL23B.
- Visibility on pause slides: reveal slides wrap the block in the existing `.if-revealed`; vote slides use the new `.if-chosen` (hidden until `.slide.chosen`). The build refuses a takeaway on a pause slide outside those wrappers, `if-chosen`/`if-revealed` on an open slide, and any leftover `.keypoint` or `.answerbox` markup.
- Removed after migration: `.keypoint` and `.answerbox` styles, `split_keypoint` / `KEYPOINT_RE`, the footer injection. `.foot` now carries only the source line. `.callout` stays for the SL07 question.
- Spacing trims so the answer never squashes: `.feedback`, `.choices`, `.takeaway` and the state wrappers are `flex-shrink:0`; choice padding 18 → 14 px, feedback padding 14 → 12, footer padding 12 → 10, `.ticks.large` cell padding 14 → 10, the SL43/SL66 wide diagram 1360 → 1330 px.
- The `key_point` field stays in `slides.json` as the summary used by presenter notes and the facilitator guide ("Key point:" rather than "Key point (on screen):"). Every point is also on screen, as the table below records.
